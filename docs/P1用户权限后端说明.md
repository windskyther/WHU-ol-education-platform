# P1 用户权限后端说明

## 本阶段交付

成员 A 当前只交付后端接口，不构建前端。P1 已实现：

- `UserProfile`：保存用户角色、头像和简介，兼容 P0 已迁移过的 Django 默认用户表。
- `EmailVerificationCode`：保存邮箱验证码哈希、用途、过期时间、使用状态和尝试次数。
- 注册邮箱验证码接口。
- 注册接口，支持 `student` / `teacher`。
- 登录接口，支持用户名或邮箱登录。
- JWT access/refresh token。
- 当前用户查询与资料修改接口。
- 角色权限基类：`IsStudent`、`IsTeacher`、`IsAdminRole`。

## 数据库迁移

```bash
cd backend
venv\Scripts\python manage.py migrate
```

本阶段不会替换 Django 默认 `auth_user` 表，而是使用 `users_userprofile` 关联默认用户表，避免 P0 已完成迁移后切换自定义用户模型造成迁移冲突。

## 前端联调入口

开发环境建议在 `.env` 中使用：

```text
EMAIL_BACKEND=django.core.mail.backends.console.EmailBackend
```

这样调用 `POST /api/auth/email-code/send/` 后，验证码会打印在后端控制台，成员 B 可直接拿验证码完成注册流程。

## 验收清单

- `POST /api/auth/email-code/send/` 能生成验证码并写入数据库。
- `POST /api/auth/register/` 使用正确验证码可创建学生或教师账号。
- 重复邮箱或重复用户名返回 `4090`。
- 错误、过期或重复使用验证码不能注册。
- `POST /api/auth/login/` 返回 `access`、`refresh` 和用户信息。
- `GET /api/users/me/` 携带 access token 可返回当前用户。
- 未登录访问 `/api/users/me/` 返回未认证错误。
