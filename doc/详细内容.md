# 在线教育平台暑期项目技术方案修订版

## 1. 项目定位

本项目定位为大学生暑期团队项目，但系统不应只是本地运行的练习项目，而应具备一定的实际可用性。

项目应满足以下要求：

1. 后端必须使用 Python。
2. 数据库必须使用 MySQL。
3. 系统应支持多人通过网址访问。
4. 系统应具备一定的并发抗压能力。
5. 功能完整度优先于复杂工程化。
6. 不追求工业级高并发，但不能只停留在本地单机 Demo。

因此，本项目推荐采用：

```text
前端：Vue 3 + Vite + JavaScript + Element Plus
后端：Python + Django + Django REST Framework
数据库：MySQL
部署：云服务器 + Nginx + Gunicorn + Django
文件存储：服务器本地 media 目录
```

------

## 2. 推荐整体架构

```text
用户浏览器

```

## 4. 为什么不再使用 SQLite

由于项目要求使用 MySQL，并且系统需要支持其他用户通过网址访问，因此 SQLite 不再适合作为正式数据库。

### SQLite 的问题

1. 更适合本地开发和小型测试。
2. 并发写入能力较弱。
3. 不适合作为多人在线访问系统的正式数据库。
4. 部署到服务器后不利于后期扩展。

### MySQL 的优势

1. 支持多人并发访问。
2. 更符合实际 Web 项目开发场景。
3. 适合课程、用户、考试、成绩、论坛等关系型数据。
4. 后续可通过索引、连接池、分页查询提升性能。
5. 更适合写进项目报告和答辩材料。

## 5. 并发抗压能力设计

本项目不追求工业级高并发，但应具备基础并发能力，能够支持多名学生同时访问课程、观看页面、提交考试和参与论坛。

## 5.1 Web 服务层

采用：

```text
Nginx + Gunicorn + Django
```

### 作用说明

| 组件     | 作用                                 |
| -------- | ------------------------------------ |
| Nginx    | 接收公网请求，处理静态资源和媒体文件 |
| Gunicorn | 多进程运行 Django 后端               |
| Django   | 处理业务逻辑和数据库操作             |
| MySQL    | 存储业务数据                         |

### 推荐 Gunicorn 配置

对于一台普通 2 核 2G 或 2 核 4G 云服务器，可以使用：

```bash
gunicorn config.wsgi:application \
  --bind 127.0.0.1:8000 \
  --workers 3 \
  --timeout 60
```

说明：

1. `workers 3` 表示启动 3 个工作进程。
2. 多进程可以同时处理多个请求。
3. Nginx 对外暴露 80 或 443 端口。
4. Gunicorn 只在服务器内部运行，不直接暴露给公网。

------

## 5.2 数据库层

MySQL 需要进行基础优化。

### 数据库设计要求

1. 重要字段建立索引。
2. 列表查询必须分页。
3. 不一次性返回大量课程、帖子、成绩数据。
4. 查询成绩、学习进度时避免复杂嵌套循环。
5. 删除数据时优先考虑软删除。
6. 外键关系设计清晰。

### 建议建立索引的字段

| 表               | 建议索引字段                       |
| ---------------- | ---------------------------------- |
| User             | username、email、role              |
| Course           | teacher_id、category、is_published |
| Chapter          | course_id                          |
| Enrollment       | student_id、course_id              |
| LearningProgress | student_id、course_id、chapter_id  |
| Exam             | course_id                          |
| Question         | exam_id                            |
| ExamSubmission   | student_id、exam_id                |
| ForumPost        | course_id、user_id                 |
| Comment          | post_id、user_id                   |

------

## 5.3 静态资源和媒体文件

前端打包后的静态资源由 Nginx 直接提供，而不是交给 Django 处理。

视频、课件、头像、证书等文件可以存储在：

```text
backend/media/
```

并通过 Nginx 暴露访问。

推荐结构：

```text
media/
├── videos/
├── materials/
├── avatars/
└── certificates/
```

### 注意事项

1. 视频文件大小需要限制。
2. 上传文件类型需要限制。
3. 下载资料前必须经过后端权限校验。
4. 视频文件不建议直接由 Django 接口传输。
5. 大文件由 Nginx 负责返回，减轻后端压力。

------

## 5.4 前端层优化

前端应避免一次性加载过多数据。

### 要求

1. 课程列表分页。
2. 帖子列表分页。
3. 学生成绩列表分页。
4. 学习记录分页。
5. 图片和视频懒加载。
6. 请求时显示 loading 状态。
7. 重复点击提交按钮时进行禁用处理。
8. 考试提交按钮需要防重复提交。

------

## 5.5 考试提交并发处理

考试提交是比较关键的并发场景。

### 要求

1. 成绩计算必须在后端完成。
2. 前端不能传最终分数，只能传答案。
3. 同一学生同一场考试只能提交一次。
4. 后端需要判断是否已经提交。
5. 提交过程建议使用数据库事务。
6. 如果重复提交，应返回错误提示。

### 推荐逻辑

```text
学生提交答案
    ↓
后端检查是否已提交
    ↓
未提交则创建答卷
    ↓
后端读取标准答案
    ↓
计算客观题分数
    ↓
保存成绩
    ↓
返回考试结果
```

## 6. 公网访问部署方案

本项目应部署到一台云服务器上，使其他人可以通过浏览器访问。

## 6.1 推荐服务器配置

最低配置：

```text
1 核 CPU
2 GB 内存
40 GB 云硬盘
Ubuntu 22.04 / 24.04
MySQL 8.0
```

更推荐配置：

```text
2 核 CPU
4 GB 内存
40 GB 或更高云硬盘
Ubuntu 22.04 / 24.04
MySQL 8.0
```

对于暑期项目展示，2 核 4G 基本足够。

------

## 6.2 访问方式

可以选择两种方式：

### 方式一：通过服务器公网 IP 访问

例如：

```text
http://服务器公网IP
```

优点：

1. 不需要购买域名。
2. 配置简单。
3. 适合课程项目展示。

缺点：

1. 访问地址不够美观。
2. 后续配置 HTTPS 不如域名方便。

------

### 方式二：通过域名访问

例如：

```text
http://example.com
```

优点：

1. 更正式。
2. 适合项目展示。
3. 后续可以配置 HTTPS。

缺点：

1. 需要购买或申请域名。
2. 需要配置 DNS 解析。
3. 部署步骤稍复杂。

------

## 6.3 部署结构

推荐将前端和后端部署在同一台服务器上：

```text
/var/www/online-edu/
├── frontend-dist/      前端打包文件
├── backend/            Django 后端项目
├── media/              上传文件
└── logs/               日志文件
```

------

## 6.4 Nginx 职责

Nginx 负责：

1. 对外监听 80 端口。
2. 返回 Vue 前端页面。
3. 代理 `/api/` 请求到 Django。
4. 提供 `/media/` 文件访问。
5. 处理静态资源缓存。

### 请求分发示意

```text
访问 /
    ↓
返回 Vue 前端页面

访问 /api/
    ↓
转发给 Django 后端

访问 /media/
    ↓
返回上传的视频、资料、头像等文件
```

## 7. 前后端交互方式

系统采用前后端分离架构。

```text
Vue 前端页面
    ↓ Axios
Django REST Framework API
    ↓ ORM
MySQL 数据库
```

### API 示例

| 方法 | 路径                      | 功能         |
| ---- | ------------------------- | ------------ |
| POST | /api/auth/register/       | 注册         |
| POST | /api/auth/login/          | 登录         |
| GET  | /api/courses/             | 获取课程列表 |
| POST | /api/courses/             | 教师创建课程 |
| GET  | /api/courses/{id}/        | 查看课程详情 |
| POST | /api/courses/{id}/enroll/ | 学生加入课程 |
| POST | /api/progress/update/     | 更新学习进度 |
| POST | /api/exams/{id}/submit/   | 提交考试     |
| GET  | /api/my/scores/           | 查看我的成绩 |
| POST | /api/courses/{id}/posts/  | 发布论坛帖子 |

## 8. 轻量但可上线的最终推荐方案

最终推荐方案如下：

```text
后端框架：Django + Django REST Framework
后端语言：Python
数据库：MySQL 8.0
前端框架：Vue 3 + Vite + JavaScript
UI 组件库：Element Plus
Web 服务：Gunicorn
反向代理：Nginx
文件存储：服务器本地 media 文件夹
部署方式：云服务器部署
访问方式：公网 IP 或域名访问
```

该方案相比纯本地版本更完整，具备以下优势：

1. 可以让其他同学、老师通过网址访问。
2. MySQL 能支持基础多人并发访问。
3. Gunicorn 多进程提高后端并发处理能力。
4. Nginx 可以高效处理前端静态文件和视频资料。
5. 技术栈仍然保持轻量，不会过度工业化。
6. 适合写入项目报告、答辩 PPT 和最终演示说明。

## 9. 不建议引入的复杂技术

虽然系统需要一定并发能力，但仍然不建议过度复杂化。

### 暂不作为必选

| 技术          | 原因                                      |
| ------------- | ----------------------------------------- |
| Redis         | 可作为后期优化，不是第一阶段必需          |
| Celery        | 异步任务复杂度较高，证书可以同步生成      |
| MinIO         | 对象存储配置复杂，本地 media 足够项目展示 |
| Kubernetes    | 完全没有必要                              |
| 微服务        | 三人项目会显著增加协作难度                |
| 视频转码服务  | 开发和部署成本过高                        |
| Elasticsearch | 搜索需求较简单，MySQL 模糊查询即可        |

## 10. 可以作为加分项的优化

如果时间充足，可以加入以下轻量优化：

1. 使用 Redis 缓存热门课程列表。
2. 使用 Redis 存储验证码或临时数据。
3. 使用 HTTPS。
4. 使用域名访问。
5. 使用 Docker Compose 管理 Django、MySQL、Nginx。
6. 使用 Locust 或 JMeter 做简单压测。
7. 使用 MySQL 慢查询日志分析性能问题。
8. 使用分页和索引展示性能优化效果。

这些内容不一定全部实现，但可以作为答辩时的技术亮点。

## 12. 最终结论

本项目不应该只使用 SQLite 和本地运行方式。根据新的要求，推荐采用：

```text
Django + DRF + MySQL + Vue 3 + Nginx + Gunicorn + 云服务器
```

这是一个比较平衡的方案：

1. 比工业级架构简单。
2. 比本地 Demo 更真实。
3. 能满足 MySQL 要求。
4. 能通过公网网址访问。
5. 具备基础并发能力。
6. 适合三人暑期项目开发。
7. 适合写进需求文档、设计文档和答辩材料。
